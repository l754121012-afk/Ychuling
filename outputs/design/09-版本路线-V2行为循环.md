# 版本路线：V2 行为循环 / V3 表现 / V4 商业验证

V1 已稳定。后续开发按四个大版本推进，美术与盈利验证不属于 V2。

## V2：完善游戏框架与行为循环

V2 不做正式美术替换，也不做 Steam Demo 验证。它只负责把当前“战斗原型”升级成一套可循环的游戏结构。

核心行为循环目标：

```text
探索新区域
 -> 看到重要目标，但暂时无法到达
 -> 为了达成目标继续探索，并在途中挑战 Boss
 -> 从主线与支线中阅读世界观
 -> 获得正向提升能力的道具/能力
 -> 回到目标点，打开之前无法到达的地方
 -> 世界发生变化，继续进入下一区域
```

### V2-A：区域与能力门框架

- 将当前单路线白盒扩展为“至少一个大区域图”，由多段探索路径连接。
- 建立可见不可达系统：目标点、封条门、断裂路线都在地图上可见，但需要能力才可进入。
- 建立能力获得表：至少 3 个正向能力，每个能力都会让旧区域出现新的可进入点。
- 完成后必须显示世界变化反馈，例如门开启、地图更新、旧区域新增支线。

### V2-B：目标、主线与支线

- 每个区域有一个“重要目标”，玩家首次进入只能看到。
- 探索路上安排至少 2 个支线目标，支线负责交代世界观与角色。
- Boss 不放在路线终点，而是放在“为了达成目标而必须深入探索”的路径上。
- 玩家需要 Boss 掉落物/能力才能真正完成区域重要目标。

### V2-C：随机派单与保存闭环

- 派单表接入随机种子：案件顺序、隐藏单、终点事件按夜班变化。
- 将固定数组房间数据改为可配置的房间/案件资源。
- 完成正式存档、休息点、地图标记、失败结算。
- 重复游玩时必须保留“地图解锁能力”，但重置每夜的具体案件组合。

### V2-D：战斗框架扩展

- 给清扫/碰撞/连携提供正式状态机与参数表，不做美术，只统一手感规则。
- 每个能力获得后，战斗至少产生一种可见的新操作或新清场方式。
- Boss 改为多阶段，但 V2 仍使用占位模型与占位动画。

## V3：表现与玩法细节优化

只有 V2 循环成立后才进入：

- 美术方向定稿与 ArtHost 资源替换。
- 正式角色、敌人、Boss、场景与 UI 表现。
- 正式动画、音效、震动、特效打磨。
- 对 V2 行为循环进行体验细节优化，例如引导、手感、演出节奏。

V3 不用于回答“是否盈利”，只负责让游戏像一个完整作品。

## V4：90 分钟大区域 Demo 验证

- 制作一个约 90 分钟的完整大区域 Demo。
- 验证整体玩法与视觉是否能吸引人重复游玩。
- 验证玩家是否对后续区域/能力/剧情产生期待。
- 用试玩数据判断是否具备盈利潜力。
- 完成 Steam 商店页素材与正式定价评估。

## 里程碑定义

- V2.1：行为循环闭环可在占位画面中完整走通。
- V2.2：至少 3 个能力、2 个支线、1 个多阶段 Boss、1 个完整大区域。
- V2.3：存档、随机派单、地图与世界变化形成系统。
- V3.1：首个可替换正式美术风格样本。
- V4.1：90 分钟 Demo 可试玩并具备商业判断依据。
