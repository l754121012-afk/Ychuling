# FIVESTAR 作者场景接管工作流

> 目的：用户在 Godot 里负责布局、模型和视觉；Codex 通过稳定语义识别功能物件并实现行为。Codex 不再根据截图猜位置，也不整读大型 `.tscn`。

## 唯一真源

- 运行时场景：`project/authoring/scenes/first_night_authoring.tscn`
- 运行时绑定：`project/authoring/runtime/first_night.json`
- 机器清单：`project/authoring/manifests/first_night_authoring.manifest.json`
- 人类摘要：`project/authoring/semantic/first_night_authoring.md`
- 工作流状态：`project/authoring/workflows/first_night.json`

只有清单里的对象才进入 Codex 的功能实现范围。纯装饰不需要登记；门、拾取、可击破、休息点、案件点、路线门等需要运行行为的物件必须登记。

## 用户如何登记物件

1. 在 Godot 右侧 `FIVESTAR 场景语义工具` 的“作者场景”里点击“打开作者场景”；也可以从 Godot 的“文件 > 打开场景”打开 `first_night_authoring.tscn`。
2. 场景里选中“行为宿主节点”。模型可以挂在它下面，也可以直接替换宿主节点类型；不要把语义登记到临时 Mesh 子节点上，除非这个 Mesh 本身就是宿主。
3. 在面板填写：
   - `semantic_id`：稳定、唯一、代码只认它，不要使用显示名。
   - `显示名（中文）`：给人和场景树快速查找用，可写“墓穴门 A”“案 1 沙发”；它会成为节点名的一部分。
   - `kind`：这个物件在玩法里是什么。
   - `behavior`：运行时需要做什么。
   - `zone_id`：物件属于哪个区域。
   - `tags`：可选检索标签。
   - `links`：它关联的其他 `semantic_id`。
   - `params JSON`：门锁条件、能力 ID、升降高度等具体参数。
4. 点击“应用语义 / 改名”。插件会同步写入节点元数据、规范名称和分组；只想改中文名时也点这里。
5. 在“可视模型（已导入）”里搜索中文名、英文 ID 或标签，固定高度列表不会再遮住预览。选中模型后可直接在“新物件中文名（可选）”里命名并点“创建选中模型为新物件”，不要求场景里先有节点；双击列表项也可直接创建。新物件会按模型分类进入 `FS_GROUP_地形`、`FS_GROUP_建筑`、`FS_GROUP_物件`、`FS_GROUP_角色` 或 `FS_GROUP_特效` 容器，随后 Scene 面板只选中分类容器，不自动展开或选中刚创建物件。要把模型挂到已有宿主时，先选中语义宿主再点“应用/替换模型”。模型会作为 `VISUAL_<model_id>` 挂在语义宿主下面；再次应用是替换语义，不会改动玩法身份。插件会先成功创建新模型，再清理宿主下旧的 `VISUAL_*` 和旧式嵌套模型，避免宝箱、水车等两个外观同时占一个位置。
6. 可先点击“一键区分未配模型”。插件只给没有模型的宿主补推荐原型，并自动用模型中文名填充空白显示名；已有模型、碰撞体和自定义显示名不会被覆盖。长墙会按宿主尺寸重复拼片，空壳或零尺寸的旧 `VISUAL_*` 会被重建；地板、区域和纯标记按规则跳过。
7. 批量识别可以进入 `ZONE` / `REGION` 分组继续查找你新加的柱子、墙、门、悬浮平台、建筑和水体；但不会把已有行为宿主内部的 `AuthoringJarBody`、模型子节点等误登记成独立物件。无法按名称识别的节点不会静默消失，会以“剩余未登记节点”列在校验输出里。
8. 插件脚本更新后要完全关闭并重新打开 Godot 项目，编辑器才会稳定加载新脚本；Dock 标题显示 `0.4.7` 表示本轮修复已加载。只重开场景不等于重载插件。这一步不会确认任何工作流节点。
9. 批量替换或手调后点击“保存当前场景”或按 `Ctrl+S`。编辑器中的修改在保存前不会写回 `.tscn`，重开场景会丢失。
10. 复制物件后必须改新的 `semantic_id`；重复 ID 会被校验拦截。

如果旧版插件曾把 GLB 内部节点重复写入作者场景，关闭 Godot 后运行：

```powershell
& 'F:\Godot\4.7.2\Godot_v4.7.2-stable_win64_console.exe' --headless --path '<工程>\project' --script 'res://tools/fs_repair_owner_duplicates.gd' -- 'res://authoring/scenes/first_night_authoring.tscn'
```

该工具会先创建 `*.owner-fix.bak`，只删除 `VISUAL_*` 预制体实例下被作者场景根重复持有的内部节点，不重建或覆盖布局。

命名规范：

```text
FS_<KIND>_<中文显示名>_<ID>
```

没有填写显示名时仍使用兼容格式 `FS_<KIND>_<ID>`。节点名中的中文只用于查找；脚本、链接和分组仍只认 ASCII 的 `semantic_id`。

自动分组：

```text
fs.semantic
fs.kind.<kind>
fs.zone.<zone_id>
fs.behavior.<behavior>
fs.tag.<tag>
```

场景树分类容器：

```text
FS_GROUP_地形
FS_GROUP_建筑
FS_GROUP_物件
FS_GROUP_角色
FS_GROUP_特效
```

每类容器只负责场景树整理，不参与语义判断，也不会覆盖物件的 `zone_id`。模型按目录分类进入对应容器；环境特效进入 `FS_GROUP_特效`。新建后只选中容器，避免 Scene 面板自动展开到内部 `VISUAL_*` 或 `EFFECT_*` 层级。生成/整理链路会给 `FS_GROUP_地形` 及其静态几何写入 Godot 原生 `_edit_lock_`，因此它们在三维视图中可见但不会误选；`FS_TERRAIN_BRUSH_地形画笔` 保持未锁定，可继续正常刷、选和改。插件不提供额外的场景组锁定按钮。

## 编辑视角与游戏视角

- `Shift+F`：像 Blender 的聚焦操作一样，按当前选中物件的世界包围盒自动取景，并从约 36° 斜上方看向物件中心；多选时会整体取景。聚焦后 `0.4.7` 会由插件接管三维视图的中键环绕、`Shift+中键`平移和滚轮缩放，不再让 Godot 原生编辑器相机按世界尺度处理；移动、环绕和缩放都限制在当前模型尺寸的舒适范围。中键拖拽仅反转水平环绕方向，上下俯仰保持原方向。
- `Ctrl+Alt+1`：从当前选中物件切入实际游戏摄像机视角；没有选中单一 `Node3D` 时，优先观察名为 `spawn` / 语义为出生点的标记，再回退到场景原点。
- `Ctrl+Alt+2`：恢复进入游戏视角前保存的编辑器摄像机位置、旋转和 FOV。
- 右侧 Dock 的“观察视图”区也提供“舒适聚焦选中物件”“切到游戏视角”和“恢复编辑视角”三个按钮，按钮文字直接标明快捷键。
- 游戏视角严格复用运行相机参数：高度 `10.5`、后移 `5.0`、FOV `52`、视线中心抬高 `1.0`。共享参数在 `project/scripts/authoring/FSGameView.gd`，避免编辑器观察值和实际游戏值分叉。
- 切换只移动 Godot 编辑器三维摄像机，不会新增相机节点，不会修改或保存作者场景。

## F5 构建试玩与完整游戏

- Dock 的“F5 运行模式”默认选择“构建试玩”。按 `F5` 后加载当前绑定的有效作者场景：正式 `*_authoring.tscn` 或白名单中的基础几何审核场景 `res://authoring/scenes/spirit_sprawl_geometry.tscn`，再生成玩家和实际游戏跟随相机；普通游戏场景和失败候选场景不会写入该目标。
- 打开有效作者/审核场景时，插件会自动把它绑定为 F5 目标。当前 `project.godot` 指向 `spirit_sprawl_geometry.tscn`；打开 `first_night_authoring.tscn` 后会切回正式作者场景。
- 构建试玩不会生成 HUD、地图、案件点、鬼、NPC、Boss、路线门或正常交互；用于检查用户正在手搭或审核的场景比例、碰撞、模型落地和玩家实际视角。玩家使用 `CharacterBody3D + move_and_slide`，会与墙、主陆区边缘、离岸房间边缘和平台侧面的实际碰撞体交互，也会受重力、跳跃和下落影响。
- 构建试玩中的玩家节点、移动/加速/跳跃/冲刺/Q/横扫/交互/追击/越障距离，以及跟随相机高度和后移一起缩放为原来的 `1/3`，用于匹配当前手搭场景的比例尺。FOV `52`、动作时长/冷却/伤害不变；这些缩放不会写入正式玩法，切回“完整游戏”后全部保持原始 `1.0` 比例。
- 没有登记 `spawn` 出生点时，玩家从作者场景原点上方约 `y=4` 开始下落。玩家优先落到作者场景实际可用的承托碰撞；只有完全没有可用碰撞面时才创建临时 `120 x 120 x 1` 碰撞地面，顶面为 `y=0`。登记出生点后，下落位置使用出生点的 X/Z。
- 当前审核场景登记了 `spawn` 和 `SURFACE_NORTH_KNOT` 承托面，玩家会从约 `y=3.97` 落下并站在主地面 `y=4.00`（构建试玩坐标）；从承托面缺口跌到出生点下方 `8m` 后，会自动回到出生点，不扣血，也不重置耐力、豆子或动量。
- 需要试玩现有完整玩法时，在 Dock 点击“F5：完整游戏”，再按 `F5`。该选择写入 `project.godot` 的 `fivestar_authoring/playtest_mode`。
- 插件脚本或 F5 目标更新后，必须完全关闭并重新打开 Godot 项目一次；只重开场景不算重载插件。

## 可视模型目录

- 目录文件：`project/authoring/assets/model_catalog.json`
- 资产来源：`project/assets/vendor/kenney/`，包括 Graveyard、Fantasy Town、Mini Dungeon 三套 CC0 原型模型。
- `model_catalog.json` 提供 141 个精选中文目录项，覆盖门、墓碑、围墙、灯具、植被、道路、建筑、地牢道具，以及雨城专用的喷泉、水车磨坊、瀑布、河流、河岸、积水、水坑和排水口。插件还会自动扫描 `project/assets/vendor/kenney/` 下全部已导入 GLB，并把精选目录与扫描结果去重后合并。
- 点击“打开模型总览”会打开只读 UI 浏览器 `project/authoring/scenes/model_gallery.tscn`：左侧是搜索、分类和模型文字列表，右侧是独立 `SubViewport` 三维实时预览、自动旋转开关、模型 ID、资源路径、复制 ID 和文件定位。它只为当前选中项生成预览实例，不会把所有目录模型铺进作者场景，也不会修改作者场景。
- Dock 里的模型浏览器使用固定高度滚动列表，下方保留同一套实时三维预览；不需要先选中场景节点，也不需要展开覆盖整个面板的下拉菜单。
- 插件把选择写进 `params.visual`，包括 `model_id`、中文名、GLB 路径、默认缩放、Y 偏移和旋转。
- GLB 只是可视壳；碰撞、门锁、拾取、案件点等行为不得依赖 GLB 路径。
- `VISUAL_*` 子节点不得登记语义。语义宿主仍是唯一行为真源，替换模型不会改变已有功能。
- “一键区分未配模型”同样不修改玩法身份；它只调用同一套 `apply_model` 路径，适合在进入第 2 节点时快速铺原型，并会修复空白或零尺寸的旧模型子节点。
- 普通模型默认按宿主的碰撞体或显式视觉底面落地；当前只有 `water_surface`、`plunge_pool_foam`、`puddle_ripple` 和 `auto_fantasy_town_cloud` 被标记为显式浮动。已有场景若还有漂浮模型，点“修正场景模型落地”即可重排；显式浮动模型会跳过。
- 旧版已经叠出的多个 `VISUAL_*` 不需要逐个删：选中该语义宿主，再应用一次想要的模型，新版会清理其余旧视觉，只保留最新模型。
- “地形与平台”快捷分类提供 24 个高频承托模型，覆盖道路、木板、平台、石阶、坡道、墙、柱体、岩石、地牢地板、半高墙和碎石障碍。它们带 `floor/platform/wall/stairs/column/obstacle` 承托类型；应用模型后插件会自动生成 `SUPPORT_*` 碰撞，地板至少保留 `0.08` 米厚度。
- 自动承托碰撞只管理插件自己生成的 `SUPPORT_*`；用户手搭的碰撞体不会被覆盖或删除。替换模型或执行落地修正后，承托碰撞会按新模型重新计算。
- 新建模型后按 `FS_GROUP_地形 / FS_GROUP_建筑 / FS_GROUP_物件 / FS_GROUP_角色 / FS_GROUP_特效` 五类归档，并且只选中对应分类容器；不会自动展开或选中刚创建的 `VISUAL_*`，避免 Scene 面板跳出当前位置。分类容器不会被记录成“上次有效语义父级”，点击 Dock 清空编辑器选择时仍沿用上次非根语义层，方便连续批量搭场景。
- 雨城水文组件位于 `project/authoring/assets/components/water/`。瀑布采用高度贴合，河道采用沿长边重复拼片，水流面片和水池溢流边采用平面拉伸，建筑附着类水流保持浮动，避免被“落地修正”压到地面。
- 右侧“水体 / 喷泉”按钮会直接筛出喷泉、瀑布、河流、河岸、水面、水洼、水坑涟漪、排水口、建筑出水和可选水车；在列表中选择模型后点“创建选中模型为新物件”。若先选中 `ZONE` 节点，组件会直接放到该区域下并自动登记中文名和稳定 `semantic_id`；没有选中节点时会放到场景根节点。
- `水体 / 喷泉`采用精确模型 ID 白名单，不按“水”字模糊搜索，因此不会混入“药水瓶”。除原有喷泉、瀑布、河道、河岸、水面、水坑、涟漪和排水口外，`0.3.3` 新增：宽瀑布水幕、细瀑布水柱、平静直河道、急流河道、墙面出水口、喷泉竖直水柱、水管细流、排水槽落流、水池溢流边、可拉伸水流面片。`0.3.5` 聚焦后的中键环绕、`Shift+中键`平移和滚轮缩放均由插件按当前物件尺寸使用近距尺度。
- 单点建筑挂模型时不读取 `AuthoringMarker` 的尺寸，因此不会被缩成不可见的标记球大小；空尺寸宿主会保留模型默认可见尺寸。
- 当前是原型替换阶段，后续可整套换成正式美术，只需要保持 `semantic_id` 不变。

## 实体地形画笔、地面绘制与地形工作流

- 右侧“地形画笔（实体）”用于直接铺设玩家可站立的草地平台、浮空平台、石质地面、道路地面和木桥/栈道；它不是贴图或贴面，生成物同时包含可视网格与 `BoxShape3D` 碰撞。
- 先选择地形、方形/圆形笔刷、`1 / 3 / 5 / 7` 格尺寸和每格厚度，再点“开启地形画笔”。厚度范围为 `0.10..2.00m`、步进 `0.02m`；在编辑器三维视图里按住左键拖动会连续铺设，松开后自动保存。
- 画笔优先创建在当前选中节点的同一级；已有的多个 `GridMap` 之间，绘制、擦除、选格和整组操作会跟随当前选中节点所在上下文，不再固定找场景里的第一个。网格被拖到其他父级后，重新选中该网格或其所在父级仍可继续编辑；没有选中节点时才回退到旧的 `FS_GROUP_地形/FS_TERRAIN_BRUSH_地形画笔` 路径。所有笔迹按 1 米网格吸附，重复刷同一格会覆盖或去重，不会为每个格子创建独立节点。
- 点“单格选择”后，左键点击已有画笔格可选中单格；按住 `Ctrl` 点击可继续加选或减选。右侧“吸取主选格”会把地形、厚度和垂直层复制到当前画笔参数。选择预览是临时节点，不会保存进场景；中键仍交给舒适聚焦的环绕/平移逻辑。
- 点“多格选择”或用 `Ctrl+Alt+3` 切换后，左键按住拖动会按当前地形、笔刷形状、尺寸和垂直层批量加选；按住 `Ctrl` 左键拖动可从已选集合中移除。完成后可用“批量应用到选中格”或“批量删除选中格”一次处理全部选中格；不再需要逐格应用或删除。
- “橡皮擦”按钮使用当前笔刷形状、尺寸和垂直层，左键按住拖动即可局部擦除；“清空画笔地形”只清空这组共享网格，不会删除原有手工地形、建筑、模型或地面贴面。
- “选中整组地形”会在场景树中选中共享 `GridMap`，随后可用 Godot 的移动、旋转和复制工具整体操作；整组状态会主动关闭画笔、橡皮擦和选格输入，避免左键被地形工具截走。按钮进入整组状态后显示“结束整组选择”并橙色高亮，再次点击即可退出；开启单格/多格选择时也会自动退出整组，立即恢复格选。
- “复制整组并偏移”会复制格子、朝向、碰撞、厚度元数据和独立 `MeshLibrary`，生成一个可继续选中和复制的独立副本，并沿原范围向侧面留一格偏移。绘制、橡皮擦、单格选择、多格选择、地面画笔和整组选择在启用时都会显示橙色高亮，关闭后恢复普通按钮样式。
- “垂直层”每档为 1 米，可在已有地面或平台上方刷浮空层；可先在地面视角确定 X/Z 位置，再提高层数继续铺。
- 右侧“地面绘制（贴面）”用于快速在大地形表面刷湿泥、青苔、石屑、水光和破败土痕；提供圆形、长椭圆和方形三种笔触，可调半径与浓度。
- 开启画笔后，在编辑器三维视图里左键点击或拖动。插件优先对地形碰撞面投射，没有碰撞时回退到 `y=0` 构建平面；松开左键后会自动保存本笔。
- 每个贴面都是无碰撞的 `GROUND_PAINT_*` 子节点，统一放在 `GROUND_PAINT_地面绘制` 下。选中单个贴面后点“删除选中绘制”只删除该视觉层，不会删除地形模型或碰撞。
- 实体画笔和地形模型仍负责承托、碰撞和玩家行走；贴面只负责视觉。它们不登记玩法语义，Codex 接管功能时也不会把画笔格子或绘制贴面当行为物件。
- 当前适合白盒阶段快速补地面变化，但本质上仍是贴面层，不是 UV 纹理笔刷。若把单个泥地模型横向拉伸后直接绘制原材质，纹理会随模型 UV 一起拉伸。
- 更推荐的地形路线是：碰撞仍用平台/地形模型；给大面积地面使用三平面 `triplanar` 材质，避免非均匀缩放造成纹理拉伸；当需要真正的高度雕刻和多图层地面绘制时，再接入 `Terrain3D` 一类地形插件。`GROUND_PAINT_` 仍可用于临时湿地、积水反光、苔藓和破损痕迹。

## 事件特效目录

- 模型负责“物体长什么样”，事件特效负责“这个物件当前是什么状态”。特效不会替换模型，而是作为独立的 `EFFECT_<effect_id>` 子节点与 `VISUAL_<model_id>` 同时存在。
- 插件把特效选择写进 `params.effect`；`params.visual` 与 `params.effect` 分开保存，导出清单也会分别保留“模型 / 事件”。
- 右侧“事件特效（不替换模型）”提供 8 种原型：案件金色信标、能力拾取光柱、可击破提示、门锁红色封印、目标金色光柱、休息恢复光环、压力机关脉冲、危险地面警示。
- Dock 可收窄：模型和特效下拉框不再按最长条目撑大侧栏，长名称在窄栏中省略显示，悬停时可在提示里查看完整名称；拖拽主画面与右侧 Dock 之间的竖向分隔条即可调整宽度。
- 选中语义宿主后选择特效并点“应用事件特效”；同一宿主只保留一个当前事件特效，重复应用会替换旧特效，但不会删除模型。点“移除事件特效”只会移除 `EFFECT_*`，模型继续保留。
- 如果旧版曾把旧模型留成额外 `VISUAL_*`，对宿主重新应用一次目标模型即可清理；清理模型不会连带删除事件特效。

## 环境特效目录

- 环境特效与事件特效分开：事件特效表示某个功能物件“当前是什么状态”，环境特效表示整个区域的灯光、大气、天气和空气粒子。二者互不替换，可同时存在。
- 右侧“环境特效”提供 9 种原型：暖色灯笼光、冷色聚光、月光、地面雾、低云层、火焰与动态光、成片雨幕、环境风线、尘埃微粒。
- 先选中区域或语义宿主作为父节点，再选择环境特效并点“创建环境特效”。它生成独立的 `ENVIRONMENT_<中文名>_<ID>_NN` 节点，可重复创建同类特效并分别移动、旋转、缩放和调参。
- 创建后插件会递归写入作者场景 `owner`；旧场景中已经存在但为空的环境节点，会在打开场景时按元数据补建内部灯光、网格或粒子。这样环境特效在保存、重启项目或进入 F5 后仍会保留。
- 选中任意 `ENVIRONMENT_` 节点后点“移除环境特效”，只删除该环境节点，不影响模型、事件特效和其他环境层。
- 环境特效属于布局视觉，不登记玩法语义；Codex 接管功能时只读取语义宿主，不会把环境特效当成行为物件。

## 剩余方块判定

“一键区分未配模型”会登记名称中含墙、门、柱、平台、建筑、水体等关键词的未登记物件，给空白语义宿主补推荐模型，并修复“旧占位方块仍与有效 `VISUAL_*` 模型重叠”的场景。它不会覆盖已有有效模型、碰撞体或自定义显示名。

处理后仍有方块时按以下顺序判断：

| 现象 | 处理 |
| --- | --- |
| `FS_FLOOR_*`、`art_key_route_floor` | 故意保留的区域地板色板，不属于未替换模型。 |
| `ZONE`、`REGION` 容器 | 作者用分组节点，不应挂可视模型。 |
| `AuthoringMarker`、出生点、休息点、案件点、Boss、导航点 | 纯逻辑点位，运行时读取坐标，不生成可视模型。 |
| 纯触发范围、`CollisionShape3D`、没有视觉的运行标记 | 保持不可见，不要为了“清方块”给它们挂模型。 |
| 柱子、墙、门、平台、建筑、普通装饰、水体 | 应由模型或显式视觉替代；先完全重开 Godot 让 `0.2.6` 生效，再重新点一次“一键区分未配模型”。 |
| 批量后仍可见的方块 | 优先视为旧占位与有效模型重叠；新版批量按钮会隐藏旧 `MeshInstance3D` 占位，但不会删除有效模型、碰撞或布局。 |
| 校验输出中的“剩余未登记节点” | 名称和关键词无法可靠识别的对象；选中语义宿主后手动填写语义，再从模型目录选择正确模型。 |
| 带中文/自定义显示名的旧方块 | 若已经挂了有效模型但显示名与你现在想要的不一致，属于人工视觉选择，不是批量失败；直接选中宿主更换模型。 |

批量完成后面板会报告“修复”数量。该数字为隐藏旧占位方块的个数；若仍有少量对象没有自动匹配，才会出现在“剩余未登记节点”里。

## 接管分类

导出的每个对象都会带 `runtime_support`：

| 分类 | 含义 | 典型对象 |
| --- | --- | --- |
| `runtime` | Codex 按语义注入并实现 | 门、路线门、拾取、可击破、升降平台 |
| `native` | 保留 Godot 原生物理，不重复挂脚本 | 可推箱 |
| `marker` | 只读取点位与坐标，不再生成可视物 | 出生点、休息点、案件点、Boss、目标、NPC、巡逻、导航 |
| `pending` | 已登记，但行为尚未实现 | E 互动、普通触发、压力机关、危险物、普通门 |
| `none` | 纯场景物件，不做运行逻辑 | 地板、装饰、普通平台 |

编辑器的“校验当前场景”会显示各类数量和错误。`pending` 不是错误，但明确表示当前会话若要实现它，必须新增对应运行时行为。

## 七节点工作流

工作流每个节点都显示负责人、操作说明、确认提示和备注框。点击“确认本节点”后会再次弹窗确认；不会自动替用户确认。

### 1 / 7 规格确认

- 负责人：AI 提供规格，用户确认。
- 提示：本轮搭哪一块、范围、入口、验收方式、不会修改哪些内容。
- 通过条件：用户明确确认规格。
- 当前状态：等待用户确认这一节点。

### 2 / 7 场景手调

- 负责人：用户。
- 提示：在作者场景中移动、替换、增删物件；行为宿主填写中文显示名和稳定 `semantic_id`，并从模型目录应用可视模型。
- 用户操作：用中文显示名管理节点，用模型目录替换颜色方块；调整布局、碰撞、灯光和视觉；逐项登记功能物件。
- 通过条件：用户确认本轮布局、显示名和可视模型已冻结。
- 注意：一旦开始手调，禁止再运行 `tools/fs_build_authoring_scene.gd`，否则会覆盖作者场景。

### 3 / 7 语义校验

- 负责人：插件 + 用户。
- 提示：点击“校验当前场景”，处理重复 ID、缺行为、无效链接或未规范命名。
- 通过条件：错误为 0；警告必须逐条确认是否有意保留。

### 4 / 7 导出并发布

- 负责人：插件。
- 提示：保存作者场景、导出 JSON/Markdown 清单，并发布为运行时真源。
- 通过条件：场景已保存、清单无错误、绑定文件已写入。
- 输出：`manifest.json`、`semantic.md`、`runtime/<region>.json`。

### 5 / 7 功能实现

- 负责人：AI。
- 提示：按清单中的 `semantic_id`、`kind`、`behavior`、`links`、`params` 和 `runtime_support` 实现。
- AI 规则：读取清单和必要脚本，不整读场景；不改用户已经冻结的布局和视觉；能跑 smoke 就提供预期输出。
- 通过条件：功能实现并有可复现验证路径。

### 6 / 7 试玩验收

- 负责人：用户。
- 提示：进入运行时场景检查视觉、碰撞、互动、门锁和状态变化。
- 通过条件：用户确认本轮试玩通过；不通过则记录问题并退回第 5 节点。

### 7 / 7 交接回填

- 负责人：AI + 用户。
- 提示：更新交接簿、运行说明和下一步；一个会话只保留一个明确任务。
- 通过条件：交接完成，可以结束本会话。

## AI 接手指令

新会话处理本工作流时：

1. 先读本文件、`outputs/SESSION-HANDOFF.md` 和 `project/authoring/manifests/<region>.manifest.json`。
2. 先看 `runtime_support`，再按 `semantic_id` 定位功能；需要看视觉时只读 `semantic.md` 或用户指定的单个节点。
3. 用户手调后只改动功能脚本，不重建作者场景；模型选择只读 `params.visual`，不能作为行为分支条件。
4. 如果发布绑定不存在或无效，运行时会回退旧 `V2RegionBuilder`，说明作者场景尚未成为有效真源。
5. 完成功能后用 smoke 验证，并把预期输出写入交接簿；之后把控制权交回第 6 节点给用户试玩。
