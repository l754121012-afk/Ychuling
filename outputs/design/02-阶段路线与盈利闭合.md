# 分阶段开发路线与行为/盈利闭合

总原则：每个阶段都以“可以运行、可以验证、可以回退”收尾。稳定后打 tag，再考虑 push。

## M0 立项与方案选择

目标：完成本次方案文档，用户选定 A/B/C，把正式 GDD 的第一页固定下来。

交付物：

- [00-立项与方案选择.md](./00-立项与方案选择.md)
- [01-原型架构与替换规则.md](./01-原型架构与替换规则.md)
- 本路线文档

## M1 参考校准 + Godot 可运行原型

目标：不需要完整内容，先把 Crypt Custodian 的“视角/布局/按键/基础动作”做成 Godot 可运行版。

步骤：

1. 打开参考版，记录控制页与手感数据，冻结 `docs/control-baseline.md`。
2. 建立 Godot 4.7.2 工程，目录按架构文档执行。
3. 实现移动、跳跃、攻击、冲刺/翻滚、互动占位。
4. 实现固定俯视角相机，先做到同屏“看起来操作布局相同”。
5. 加入一个测试房间、一个只会挨打的占位敌人和一个可触发“送客/清场”占位事件。

验收：

- 玩家用键盘和手柄分别试参考版与原型版，逐项对照移动、攻击、跳跃、冲刺、互动。
- 我方把差异记录为“可修复清单”，不把“原版手感难抄”当结论。
- 打 tag，例如 `m1-control-shell`。

## M2 三房间 + 一 Boss 垂直切片

目标：把选定方案的核心“清场循环”放进一个可以玩 10-20 分钟的切片。

步骤：

1. 根据选定方案做 3 个房间模板，先出黑白布局图并确认。
2. 房间连接与“看到门锁 -> 拿能力 -> 回来开门”的最小闭环。
3. 1 个 Boss 的三幕结构：挑衅、破绽、送客/谢幕。
4. 接入至少 2 件占位道具，证明“拿到道具后行为确实改变”。
5. 加暂停、保存、失败回起点但不惩罚性清空。

验收：

- 玩家能不看教程完成一条完整“清场”行为链。
- 试玩后玩家能说出“这门一开始不能开，拿到 X 后我回来开了它”。
- 打 tag，例如 `m2-three-room-slice`。

## M3 Isaac 式构筑与 HK 式推进最小融合

目标：验证核心公式不是“三个游戏轮流玩”，而是同一次击打同时产生三种价值。

步骤：

1. 道具池与 3-5 个基础 synergy 的数值框架。
2. 房间种子、房型池、清场奖励的随机连接，先保证每次开局有差异。
3. 能力门/地图标记/快捷往返的最小实现。
4. 选定方案独有的“清场语言”，例如 A 的工单、B 的 NG、C 的借据。
5. 新玩家的前 3 分钟引导脚本：第一次攻击、第一次清场、第一次见到锁。

验收：

- 随机不会让房间失去可读性。
- 道具获得后玩家能在 30 秒内看到改变。
- 行为头尾闭合：锁是可见的，钥匙获得是可见的，回来开门的结果是可见的。
- 打 tag，例如 `m3-fused-loop`。

## M4 风格化美术替换

目标：把几何体占位换成“猫和老鼠式荒诞戏剧”风格资产。

步骤：

1. 做视觉风格页：角色轮廓、颜色、材质、阴影、镜头色温、UI 字体。
2. 先替换玩家、扫把、3 个敌人、1 个 Boss、1 套房间地板墙。
3. 加入夸张动画：受击拉长、旋转飞走、贴地滑行、门弹开、清场光效。
4. 逐场景截图/录屏验证：明暗、反馈、命中、关键道具是否一眼可读。

验收：

- 白盒阶段的碰撞与内容数值不因美术替换崩坏。
- 每一个攻击/受击/清场事件在截图与录屏中都有明确视觉反馈。
- 打 tag，例如 `m4-style-pass`。

## M5 行为闭合、demo 与盈利路径

目标：让玩家从第一次打开到购买/推荐形成一条闭合路径。

步骤：

1. 明确三种时间层：单场战斗 1-3 分钟、一轮夜班/一次房间串联 15-25 分钟、一个完整存档路线 40-60 分钟。
2. 试玩数据埋点：第一击、第一死、第一清场、第一次开门、第一次道具组合、退出原因。
3. Steam 商店页素材、Demo 范围、愿望单钩子；免费 Demo 做正式游戏第一章的前半段。
4. 正式版定价与后续更新计划：不做抽卡；付费点来自完整单机内容、后续可预期的模式/章节扩展。
5. 每次外部试玩用统一表记录：看到了什么、学会了什么、在哪弃坑、下次愿不愿意回来。

验收：

- 新玩家前 15 分钟至少完成一次“能力获得 -> 回到旧锁 -> 世界变化”的正反馈。
- 试玩后玩家能说出一个原版 Crypt Custodian/Isaac/Hollow Knight 没有的理由。
- 有 Steam 商店页与可运行 Demo 作为下一步交付物。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 只复刻原版手感，无独特性 | 每个阶段强制保留“送客/清场演出”模块并做真实验证 |
| Isaac 式随机把内容做散 | 第一版房间池非常小，靠组合设计而非堆量 |
| HK 式大地图内容成本过高 | M2 只做 3 房间 + 1 Boss 的闭合路径，不先扩图 |
| 换模型后手感崩坏 | 美术与玩法解耦，见架构文档第 4 节 |
| 盈利只靠“卖情怀” | M5 用 demo、商店页、埋点和试玩记录做市场依据 |

每次方案更新都会同步更新本路线表与记忆，稳定版本才打 tag/push。

### A+2《五星除灵》的路线调整

若确认 A+2《五星除灵》，M1 内容不变，仍是 Crypt Custodian 式键位/镜头可运行壳。M2 的“3 房间 + 1 Boss”调整为“1 条短派单路线 + 3 个上门现场 + 1 个收工事件”；赶场先做成轻量快穿，上门清场承担主要验证。M3 再验证“派单表 + 闹事组合 + 好评经济”的随机开局与多收工结局。

M1 试玩反馈与 M2 进度（2026-09-08）：

- 已修复：边界墙加高，移速 7.2 -> 6.4，加速度 18 -> 14。
- M2 路线白盒已完成第一版：主场景 `M2Route.tscn`，3 个现场 + 收工大鬼流程 smoke 通过。
- M2 战斗反馈已补：清扫命中框对齐扫把并降低判定高度；敌人被击退；鬼攻击分挥击/弹射光球/红色落点/冲锋，玩家有 3 点状态与受击弹飞/短暂无敌。
- 新增特色基础：高速碰撞轻反弹、鬼撞鬼速度传导，形成“弹珠式清场”雏形，扩展方案见 06 文档。
- 状态语义修正：鬼攻击前摇改为蓝色闪光；黄色身体+脚下黄圈才是可 E 送走的常驻状态，不会自动恢复。
- 下一步：试玩 M2 的 3 单 + 收工节奏，再进入随机派单与 M3。
